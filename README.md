# 도메인 특화 LLM 파인튜닝 — 데이터 설계부터 자기개선 루프까지

> 국가공무원 복무규정 Q&A를 도메인 특화 AI로 만들며,
> **데이터 설계 → 파인튜닝 → RAG → 결합 → DPO → 자기개선**까지
> 빅테크의 후학습(post-training) 파이프라인을 소규모로 직접 재현한 개인 연구입니다.
> 각 단계를 "가설 → 실험 → 관측 → 처방"의 사이클로 진행하며, 25개 스크립트로 전 과정을 구현했습니다.
> *(현재도 실험과 학습을 이어가고 있습니다.)*

## 이 프로젝트가 보여주는 것

단순히 "파인튜닝을 돌려봤다"가 아니라, **파인튜닝이 무엇을 할 수 있고 무엇을 할 수 없는지**를
실험으로 규명하고, 각 실패의 원인을 데이터로 진단해 다음 처방을 설계한 과정입니다.

핵심 결론 하나로 요약하면 — **사실은 RAG가, 행동은 파인튜닝이.**
이 원칙을 말로 외운 게 아니라, 세 가지 구성을 비교 실험해 직접 재현했습니다.

## 실험 여정 (run1 → run7)

### 1단계. 데이터가 전부다 (run1 → run3)
- **run1**: 과적합을 일부러 일으켜, train loss는 내려가는데 val loss가 오르는 "암기 구간"을 계기판으로 관측
- **run2**: 말투("제N조에 따르면…")는 완벽한데 조문 번호·내용은 창작 → **사실 밀도 부족**으로 진단
- **run3**: 모델·학습량을 고정하고 **데이터만** 사실 단위로 증강 → 키워드 적중률 12.5% → 75%, 중국어 유출 2건 → 0건
- **결론**: 파인튜닝의 성패는 모델이나 학습량이 아니라 **데이터 설계**가 결정한다

### 2단계. 검색의 품질은 청킹이 결정한다 (RAG)
- 검색 실패의 절반이 "여러 주제가 섞인 긴 조문"에 몰린다는 것을 실패 집계로 발견
- 긴 조문을 항·호 단위로 재분할하되 **머리 문장을 붙여 맥락 보존** → 검색 정확도(hit@3) 90.5% → 93.5%
- 변인은 청킹 하나만 바꿔 효과를 격리 검증

### 3단계. 결합의 필요성을 3자 비교로 증명 (run4)
- 파인튜닝 단독 / 원본+RAG / 파인튜닝+RAG 세 구성을 비교
- 원본+RAG는 "…17일입니다. 제공된 규정에서 확인되지 않습니다" 같은 **자기모순**을 일으킴
- 파인튜닝+RAG만 전 항목 정상 → "사실은 RAG, 행동은 파인튜닝"을 데이터로 재현
- run4에서 "경우 구분" 행동이 다수결에 밀려 발현 안 되는 **행동 충돌**을 진단하고, 정책 일관화로 해결(run4b)

### 4단계. 빅테크 후학습 코스 (run5 → run7)
- **CoT 증류(run5)**: 풀이 궤적을 사람이 아닌 **코드로 생성**(규정 표를 함수로 구현 → 궤적에 환각이 원천적으로 없음). 학습에 없던 숫자 조합으로 **홀드아웃 실험** → 외운 게 아니라 절차를 배웠음을 검증
- **DPO(run6)**: 실제 관측된 실패 4유형을 rejected로 재현한 선호 쌍으로 행동 교정. 이 과정에서 **재양자화가 학습을 지우는 사건**을 만나(4bit 병합 시 LoRA 조정이 반올림에 갈려나감, 6/6→3/6), 3중 비교로 원인을 격리하고 16bit 병합으로 해결
- **자기개선 루프(run7)**: 모델이 답을 여러 개 생성 → 검증기로 채점 → 합격작만 재학습(STaR). 정답률 63% → 76%. **STaR의 구조적 한계**(합격 0건인 절차는 학습 재료가 0건이라 개선 경로가 없음)를 직접 관측

## 대표 코드

### 검색의 실체는 행렬곱 한 줄 (`rag_search.py`)
벡터를 정규화해 두면 코사인 유사도가 내적과 같아진다. 조각 수가 적어 벡터DB 없이 numpy로 검색의 원리를 그대로 구현.
```python
def search(self, query: str, top_k: int | None = None) -> list[tuple[str, float]]:
    q_vec = self.model.encode([query], normalize_embeddings=True)[0]
    scores = self.vectors @ q_vec               # <- 검색의 전부 (코사인 유사도)
    order = np.argsort(scores)[::-1][:k]
    return [(self.chunk_ids[i], float(scores[i])) for i in order]
```

## 이 실험에서 익힌 것

- **평가 없이는 개선도 없다**: loss는 나침반일 뿐 심판이 아니며, 최종 판정은 항상 행동 평가로. 모델을 만지는 모든 단계 뒤에는 평가를 다시 돌린다("파일이 생겼다고 성공이 아니다")
- **환각은 기계적으로 막는다**: 답변의 숫자를 원문과 대조하고, 데이터는 Pydantic 스키마로 검증(한글·한자 비율 미달 시 자동 탈락)
- **파이프라인 전 과정을 직접 다룬다**: 데이터 파싱·검증부터 학습·병합·양자화까지 손대며, 문제가 어느 단계에서 비롯됐는지 짚어내는 눈을 길렀다
